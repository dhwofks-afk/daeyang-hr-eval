(11/3: 자기관찰은 화면에서 삭제. 아래 자기관찰 부분은 기록으로만 남긴다. "평가 의견" → "종합 의견")

## 0. 목표
자기평가를 쓰는 김에 **자기관찰 · 건의 · 만족도**를 같은 화면 맨 끝에서 받는다.
건의·만족도는 **작성자를 알 수 없게** 받는다 (관리자도 누가 썼는지 모른다).
여기서 받은 내용은 건의함·만족도 보기(③)와 요약·면담 리포트의 재료가 된다.

## 1. 페이지·폴더
| 주소 | 폴더 | 이번 범위 |
|---|---|---|
| /my/evaluations?case=번호 (자기평가 건일 때만) | my-evaluations | ✅ 자기평가 작성 화면 **맨 끝**에 세 묶음 추가 |
- 새 주소·새 페이지 없음. routes.tsx는 고치지 않는다
- 팀장·임원 평가, 상향 평가 화면에는 보이지 않는다 (자기평가 건에만)
- 대상: 자기평가 건이 있는 팀원·팀장. **임원은 이번 범위에서 제외** [임시 결정]

## 2. 화면 구성 (자기평가 작성 화면, 평가 의견 아래 · [임시 저장][제출] 위)

### 2-1. 자기관찰 (필수 [임시 결정])
| 항목 | 입력 | 서버 칸 |
|---|---|---|
| 업무량 | 1~5 버튼 (필수) | workload |
| 난이도 | 1~5 버튼 (필수) | difficulty |
| 적성 | 1~5 버튼 (필수) | aptitude |
| 업무 만족도 (서버 칸: satisfaction) | 1~5 버튼 (필수) | satisfaction |
| 대인관계 | 1~5 버튼 (필수) | relationships |
| 이동 희망 | 1~4 중 하나 (필수) | transfer_wish |
| 희망 부서 | **부서 목록에서 고르기** (선택) [임시 결정] | wish_department (부서명을 글로 저장) |
| 현재 주요 업무 | 글 (선택) | main_work |
| 기타 의견 | 글 (선택) | other_opinion |
- 1~5 버튼은 평가 문항과 같은 모양 (크게, 휴대폰에서 누르기 쉽게)
- 점수 뜻(1·5가 무엇인지)과 이동 희망 1~4 문구: 임시 문구를 넣고 **[회사 확인 중]** 표시
  - 임시 문구 예: 1~5 "1 매우 낮음 ~ 5 매우 높음", 이동 희망 "1 원하지 않음 / 2 고려 중 / 3 희망 / 4 적극 희망"
- [자기관찰 저장] 버튼. "본인과 관리자만 볼 수 있습니다" 안내

### 2-2. 건의 (선택)
- 글 입력 칸 1개 + [건의 보내기]
- **여러 번 보낼 수 있다** [임시 결정]. 보낼 때마다 한 건씩 추가된다
- 안내: "작성자는 저장되지 않습니다. 보낸 뒤에는 고치거나 다시 볼 수 없습니다."
- 비워 두어도 된다 (건의만 선택 항목 — CLAUDE.md)

### 2-3. 만족도 (필수 [임시 결정])
- 점수 1~5 (필수) + 의견 (선택) + [만족도 제출]
- 질문 내용: 임시 문구를 넣고 **[회사 확인 중]** 표시
  - 임시 문구 예: "이번 인사평가 과정에 얼마나 만족하셨나요?"
- 이미 낸 사람에게는 입력 칸 대신 "이번 회차 만족도를 제출했습니다"만 보인다 (제출 여부만 읽음, 내용은 읽지 않음)
- 안내: "작성자는 저장되지 않습니다. 한 번만 낼 수 있습니다."

## 3. 동작
- **평가 중이고 결과 공개 전일 때만** 쓰고 보낼 수 있다 (서버 cycle_is_open: 상태 "평가 중" + 결과 공개 아님)
  - 그 밖에는 세 묶음 모두 입력할 수 없고 이유를 보여 준다
- 자기평가 [제출]과의 관계 [임시 결정]
  - **자기관찰 저장 + 만족도 제출이 끝나야** 자기평가 [제출]이 된다
  - 안 끝났으면 제출하지 않고 그 묶음으로 이동해서 표시한다 (평가 문항 빠짐과 같은 방식)
  - 건의는 선택이라 조건에 들어가지 않는다
- 자기관찰
  - [자기관찰 저장] → 내 자기관찰 한 줄 저장 (없으면 추가, 있으면 고치기)
  - 점수 6개(1~5 다섯 개 + 이동 희망)는 서버에서 비울 수 없다 → 6개를 모두 골라야 저장된다
  - **자기평가를 제출한 뒤에는 읽기 전용** [임시 결정] (서버는 평가 중·공개 전이면 고치기를 허용하므로 화면에서 막는다). 자기평가가 반려되면 자기평가와 함께 다시 고칠 수 있다
- 건의
  - [건의 보내기] → 추가만 한다 (회차·내용 두 칸만 보냄)
  - 보낸 뒤 입력 칸을 비우고 "보냈습니다"만 보여 준다. **보낸 내용을 다시 읽지 않는다** (직원은 읽기 권한이 없다)
  - 공백만 있으면 보내지 않는다 (서버도 거부)
  - 자기평가 제출 후에도 평가 중·공개 전이면 보낼 수 있다
- 만족도
  - [만족도 제출] → **submit_satisfaction(회차, 점수, 의견)으로만** 보낸다 (표에 직접 쓰지 않음)
  - 서버가 내용(작성자 없음)과 제출 여부를 한 번에 저장. 이미 냈으면 "이미 만족도를 제출했습니다." 거부
  - 보낸 뒤 입력 칸을 비우고 제출 완료 표시만. **보낸 내용을 다시 읽지 않는다**
- 익명을 지키기 위해
  - 건의·만족도 내용은 화면 메모리·브라우저 저장소(localStorage 등)에 남기지 않는다
  - 날짜·시각을 함께 보내지 않는다 (표에 칸도 없음)

## 4. 데이터

### 쓰는 표 (07-서버추가 2·3번, 10-데이터설계 10~12번)
| 표 | 읽기 | 쓰기 |
|---|---|---|
| 평가 설정 cycles | 상태, 결과 공개 여부 | — |
| 부서 departments | 부서명 (희망 부서 목록) | — |
| 자기관찰 self_observations | 내 것 | 내 것 추가·고치기 (회차·직원 칸은 못 바꿈) |
| 건의 suggestions | — (읽지 않음) | 추가만: cycle_id, content |
| 만족도 satisfaction | — (읽지 않음) | — (submit_satisfaction이 씀) |
| 만족도 제출 여부 satisfaction_done | 내 것 (냈는지만) | — (submit_satisfaction이 씀) |

### 가짜 데이터 단계 (제안)
- 저장 자리는 my-evaluations 폴더의 evaluation-store.ts에 더한다 (화면 메모리, 새로고침하면 처음 값)
- 건의·만족도는 가짜 단계에서도 "보냈다"는 사실만 남기고 내용을 다시 꺼내 보여 주지 않는다
- 사람·회차·부서는 기존 가짜 데이터(people.ts, evaluations.ts, scores.ts)를 읽기만 한다

### 실제 연결
- src/lib/supabase.ts로 위 표를 읽고 쓴다. 만족도는 rpc("submit_satisfaction", …)
- 권한은 서버가 지킨다 (005 권한 규칙). 화면에서 막아도 서버 규칙이 진짜 잠금이다
- 임시 결정 2·3(제출 조건, 제출 후 읽기 전용)은 지금 서버 규칙에 없어 화면에서만 지킨다

## 5. 볼 수 있는 사람

|---|---|---|---|
| 자기관찰 | 쓰기·읽기 | **못 봄** | 읽기 |
| 건의 내용 | 보내기만 (다시 못 봄) | 못 봄 | 읽기 (작성자 모름) |
| 만족도 내용 | 보내기만 (다시 못 봄) | 못 봄 | 읽기 (작성자 모름) |

- 관리자 쪽 화면(건의함·만족도 보기)은 이 문서 범위가 아니다 (③)

## 6. 하지 않을 것
- 건의함·만족도 보기 (관리자 화면, ③)
- 건의 고치기·지우기, 보낸 건의 다시 보기
- 만족도 다시 내기·고치기
- 건의·만족도에 작성자·날짜·시각 남기기
- 임원의 자기관찰·건의·만족도 [임시 결정]
- 자기평가 문항·점수 계산 변경

## 7. 완료 체크리스트
- [ ] 자기평가 작성 화면 맨 끝에만 세 묶음이 보이고, 팀장·임원·상향 평가 화면에는 없다
- [ ] 자기관찰 점수 6개를 다 고르지 않으면 저장되지 않고, 저장 후 다시 들어오면 내 값이 남아 있다
- [ ] 희망 부서는 부서 목록에서 고른다
- [ ] 자기관찰 저장·만족도 제출 전에는 자기평가 [제출]이 되지 않고 그 묶음으로 이동한다
- [ ] 자기평가 제출 후 자기관찰은 읽기 전용이다
- [ ] 건의는 비워 두어도 되고, 여러 번 보낼 수 있다. 보내면 칸이 비고 "보냈습니다"만 보이며, 보낸 내용이 화면 어디에도 다시 나오지 않는다
- [ ] 만족도는 submit_satisfaction으로만 보내고, 한 번 낸 뒤에는 다시 낼 수 없다 (제출 완료 표시)
- [ ] 임시 문구(자기관찰 척도·이동 희망·만족도 질문)에 "회사 확인 중" 표시가 보인다
- [ ] 평가 중이 아니거나 결과 공개 후에는 세 묶음 모두 보낼 수 없고 이유가 보인다
- [ ] 건의·만족도 내용이 브라우저 저장소에 남지 않는다
- [ ] (실제 연결 후) 팀장으로 로그인해 팀원의 자기관찰이 보이지 않는다
- [ ] PC·모바일에서 가로 스크롤 없음, 16px보다 작은 글씨 없음
- [ ] pnpm build, pnpm exec tsc --noEmit 통과
