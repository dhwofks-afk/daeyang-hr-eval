## 2. 새 표 4개 (10-데이터설계 9~12번)
| 표 | 칸 | 누가 쓰고 읽나 |
|---|---|---|
| 반려 기록 return_logs | 회차, 평가 건, 사유(필수), 처리한 사람·시각(서버가 채움) | 관리자만 (반려 함수로만 추가). 평가자는 자기 평가 건의 최근 사유만 서버 함수로 받음 |
| 자기관찰 self_observations | 회차, 직원(내부 번호), 업무량·난이도·적성·만족도·대인관계(1~5), 이동 희망(1~4), 희망 부서·현재 주요 업무·기타 의견(글) | 본인 쓰기·읽기, 관리자 읽기. 팀장·임원은 못 봄 |
| 건의 suggestions | 회차, 내용 (**날짜·시각 없음**) | 직원은 추가만, 관리자만 읽기. **작성자 칸 없음** (관리자도 누가 썼는지 모름) |
| 만족도 satisfaction + 만족도 제출 여부 satisfaction_done | 내용 표: 회차, 점수(1~5), 의견(선택) (날짜·시각 없음) / 제출 여부 표: 회차, 직원 | 내용 표엔 작성자 없음. 한 사람이 한 번만 내도록 제출 여부는 따로 기록. 둘을 서버 함수가 한 번에 저장 |

- 건의·만족도 내용에 날짜·시각을 두지 않는 이유: 27명 규모에서는 날짜만으로도 "그날 제출한 사람"으로 작성자를 짐작할 수 있어서. 어느 해 것인지는 회차 칸으로 구분한다
- 화면에서 보여 주는 순서는 정해지지 않는다 (섞여 보여도 됨)
- 알아 둘 점: 데이터베이스 기준 익명이다. Supabase 접속 기록(로그)에는 요청한 계정이 남을 수 있다 (인계 문서에 적기)

## 3. 서버 함수 5개
| 함수 | 누가 | 하는 일 | 쓰는 화면 |
|---|---|---|---|
| start_cycle(회차, 시작일, 마감일) | 관리자 | "평가 전" → "평가 중", 날짜 저장. 평가 건이 없으면 규칙대로 만든 뒤 시작 | 평가 설계 [평가 시작] |
| update_deadline(회차, 마감일) | 관리자 | 평가 중 마감일 수정 | 평가 설계 [마감일 수정] |
| return_case(평가 건, 사유) | 관리자 | 평가 중·공개 전·제출 상태일 때만. 상태 "반려" + 반려 기록 추가 | 진행 관리 [반려] |
| publish_results(회차, 결과 목록) / unpublish_results(회차) | 관리자 | 화면이 scoring.ts로 계산한 결과를 받아 확정 결과에 저장하고 공개 켜기 / 공개 끄기(확정 결과는 남김) | 리포트 [결과 공개]·[공개 취소] |
| new_cycle(이름) | 관리자 | 직전 회차의 설정·문항을 복사해 "평가 전" 새 회차 만들기 + 재직·평가 제외 아닌 직원으로 평가 건을 규칙대로 미리 만듦 | 데이터 관리 [새 회차] |
| submit_satisfaction(회차, 점수, 의견) | 직원 | 이미 냈으면 거부. 내용(작성자 없음) + 제출 여부를 한 번에 | 평가 작성 추가 |
| my_return_reason(평가 건) | 평가자 본인 | 내 평가 건의 최근 반려 사유 | 평가 작성 (반려 표시) |

### 평가 건을 언제 만드나 (정한 것)
- 새 회차를 만들 때 규칙대로 **"평가 전" 상태로 미리** 만들어 둔다
- 평가 관계 설정 화면(오재란 ③)에서 평가 전에 이걸 고친다
- [평가 시작]은 상태를 바꾸고 잠근다 (평가 건이 하나도 없을 때만 그 자리에서 만든다)
- 규칙은 5-3 seed와 같다: 자기 / 같은 부서 팀장 / 임원 / 상향(팀원 → 팀장)

### 결과 공개를 화면이 계산해서 보내는 이유
점수 계산(scoring.ts)이 화면 쪽에 있어서, 서버가 같은 계산을 다시 만들면 두 곳이 어긋날 수 있다. 관리자만 부를 수 있는 함수라 관리자 화면의 계산을 믿는다.

## 4. 잠금 장치
| 언제 | 막는 것 |
|---|---|
| 회차가 "평가 중" 이후 | 그 회차 문항 추가·수정·삭제, 평가 건 추가·삭제, 평가 건의 대상·평가자 변경 (관리자도) |
| 결과 공개 후 | 반려 (기존 잠금: 가중치·KPI·보정·등급 비율은 003에 이미 있음) |

## 5. 하지 않을 것
- 명단 업로드 (데이터 관리 ④에서 Edge Function으로)
- 면담 지원 AX
- 안내·독촉 발송

## 6. 완료 체크리스트
- [ ] 005·006 실행 후 확인 쿼리: 새 표 5개(만족도 2개 포함), 새 함수 7개, 권한 규칙 추가분이 실제로 있다
- [ ] 직원으로 로그인해 건의를 추가할 수 있고, 건의 목록은 읽을 수 없다
- [ ] 관리자가 건의를 읽어도 작성자를 알 수 없다 (칸 자체가 없음)
- [ ] 만족도는 한 사람이 두 번 낼 수 없다
- [ ] 자기관찰은 본인과 관리자만 읽힌다 (팀장으로 로그인해 팀원 것이 안 보임)
- [ ] 반려: 제출 건만 되고, 사유 없으면 거부, 공개 후 거부. 반려 기록이 쌓이고 평가자는 사유를 받는다
- [ ] 평가 시작 후 문항 수정·평가 건 추가가 거부된다
- [ ] new_cycle로 회차 2를 만들면 평가 건이 "평가 전"으로 생기고, 회차 1 데이터는 그대로다 (확인 후 회차 2는 지운다)
- [ ] publish → 확정 결과 저장·공개, unpublish → 공개 꺼짐·확정 결과 남음
- [ ] 로그인 전(anon)에는 새 함수·표 모두 막힌다
