# 평가 관계 설정 — 담당: 오재란
위치: 사람·조직 > 평가 관계 (/admin/people/relations, 폴더 people-relations)

## 0. 목표
평가를 시작하기 전에 관리자가 "누가 누구를 어느 단계로 평가하는지"를 확인하고 고친다.
평가 건은 새 회차를 만들 때 규칙대로 "평가 전"으로 미리 생기므로(07-서버추가), 이 화면은 그걸 **확인·수정**하는 곳이다.

## 1. 화면 구성
1. 위쪽: 회차 선택 + 회차 상태 표시
   - "평가 전"이면 수정 가능, "평가 중" 이후면 읽기 전용 + "평가가 시작되어 수정할 수 없습니다"
2. 부서 선택, 이름 검색
3. 관계 표 (한 줄 = 평가 대상 한 명)
   | 평가 대상 | 부서·직급·역할 | 자기평가 | 팀장 평가자 | 임원 평가자 | 상향 평가자 (팀장만) | 임원 상향 평가자 (임원만) |
   - 기본 규칙: 임원 평가자 = 같은 부서 임원, 없으면 직급이 가장 높은 임원(같으면 내부 번호 작은 사람). 임원 상향 = 같은 기준의 반대 방향(같은 부서 팀원·팀장 → 임원)
   - 팀장 평가자·임원 평가자: 고르기 칸 (재직 직원 중). 비우면 그 단계 없음
   - 상향 평가자·임원 상향 평가자: 이름 칩 여러 개 + [추가] [×]
   - 규칙과 다른 줄은 색으로 표시 ("규칙과 다름")
4. 아래 버튼: [저장] [규칙대로 다시 만들기]
   - 규칙대로 다시 만들기: 확인 창 "고친 내용이 모두 사라집니다" → 5-3 규칙으로 다시 생성 (답이 있는 평가 건은 그대로 둔다)
5. 평가 제외·퇴사자는 표에 나오지 않는다 (맨 아래 "평가 대상 아님 n명" 접기)

## 2. 동작
- 저장 → 서버 함수로 바뀐 평가 건만 추가·변경·삭제
- 같은 대상·단계·평가자 중복은 거부
- 자기 자신을 팀장·임원·상향·임원 상향 평가자로 넣을 수 없다
- 평가 중 이후에는 서버 잠금(006)이 모두 거부한다. 화면도 막는다

## 3. 서버 (오재란이 함께 만든다: 서버 추가-2)
지금 권한 규칙상 관리자도 평가 건의 평가자를 직접 바꾸거나 지울 수 없다 (002에서 상태·의견·제출 시각만 수정 허용, 삭제 권한 없음). 그래서 함수가 필요하다.
| 함수 | 하는 일 |
|---|---|
| save_relations(회차, 변경 목록) | 평가 전 회차만. 평가 건 추가·평가자 변경·삭제를 한 번에. 중복·자기 자신 검사 |
| regenerate_cases(회차) | 평가 전 회차만. 그 회차 평가 건을 지우고 규칙대로 다시 생성 |
- 파일: supabase/migrations/007_relations.sql
- 실행 후 확인 쿼리 + 동작 시험(rollback)으로 확인

## 4. 데이터
| 표 | 읽기 | 쓰기 |
|---|---|---|
| 평가 설정 | 회차·상태 | — |
| 직원 | 이름·부서·직급·역할·평가 제외·재직 | — |
| 평가 건 | 대상·평가자·단계 | 서버 함수로만 |
- 가짜 데이터 단계는 건너뛰고 바로 실제 연결한다 (서버가 이미 있음)
- 시연: 회차 1은 평가 중이라 읽기 전용. 수정 장면은 new_cycle로 만든 "평가 전" 회차로 보여 준다

## 6. 하지 않을 것
- 관계도 그림(다이어그램) — 조직도 메뉴에서
- 엑셀로 관계 올리기

## 7. 완료 체크리스트
- [ ] 회차 1(평가 중)은 읽기 전용이고 안내 문구가 보인다
- [ ] 평가 전 회차에서 팀장 평가자를 바꾸고 저장하면 평가 건이 바뀐다
- [ ] 상향 평가자 추가·삭제가 된다
- [ ] 자기 자신·중복은 저장되지 않는다
- [ ] 규칙과 다른 줄이 표시되고, 규칙대로 다시 만들기가 된다
- [ ] 평가 제외·퇴사자가 표에 없다
- [ ] 직원 계정으로는 함수가 거부된다
- [ ] build·tsc 통과
