# 진행 관리 — 담당: 박수빈 (평가 작성 다음)
기한: 화면(가짜 데이터) → 11/4 실제 데이터 연결

## 0. 목표
관리자가 "누가 아직 평가를 안 했는지" 한눈에 보고, 잘못 제출된 평가는 사유와 함께 되돌린다.
안내·독촉 발송은 하지 않는다 (미팅에서 제거).

## 1. 페이지·폴더
| 주소 | 폴더 | 내용 |
|---|---|---|
| /admin/progress | progress | 응답 현황 |
| /admin/progress/returns | progress-returns | 제출 반려 기록 (골격 있음) |

## 2. 화면 구성
### 응답 현황
1. 위쪽 요약: 전체 제출률, 단계별(자기·팀장·임원·상향) 제출 n/N
2. 보기 전환: [평가자 기준](기본) / [평가 대상 기준]
   - 평가자 기준: 사람마다 "해야 할 평가 n건 중 m건 제출", 미완료자가 위로
   - 평가 대상 기준: 사람마다 "받을 평가 n건 중 m건 제출"
3. 필터: 부서 / 단계 / 상태(작성 전·작성 중·제출·반려), 검색: 이름
4. 표 (한 줄 = 평가 건): 평가 대상 · 부서 · 단계 · 평가자 · 상태 · 제출 시각 · [반려]
   - [반려]는 "제출" 상태에만 보인다
### 제출 반려
- 반려 기록 목록: 언제 · 어떤 평가 건(대상·단계·평가자) · 사유 · 처리한 사람
- 지금 반려 상태로 다시 쓰는 중인 건 표시

## 3. 동작
- [반려] → 사유 입력 창(필수) → 확인 → 평가 건 상태 "반려" + 반려 기록 한 줄 추가 (서버 함수가 한 번에)
- 반려는 회차가 "평가 중"이고 결과 공개 전일 때만 가능
- 반려된 평가자는 평가 작성 화면 위에서 "관리자가 반려했습니다: (사유)"를 본다 (06-평가작성에 연결)
- 반려 기록은 지우거나 고칠 수 없다
- 상향 평가의 평가자 이름도 보인다 (관리자는 신원을 볼 수 있는 규칙)
