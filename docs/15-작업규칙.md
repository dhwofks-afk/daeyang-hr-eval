## 2. 011 실행 실패
- 오류: `duplicate key value violates unique constraint "positions_sort_order_key"` (직급 순서 번호 겹침)
- 원인: 기존 직급 순서를 +100 비켜 둔 값(과장 104 등)과 새 직급 번호가 겹쳤다.
- 고침: score-v2 커밋 48f6ae1. +1000으로 비켜 두고 새 직급은 2001부터 넣은 뒤 1~15로 다시 매긴다. 전체를 begin/commit으로 묶고, 다시 실행해도 안전하게(이미 있으면 건너뛰기) 했다. **아직 실행 전.**

중간 적용 여부 확인 쿼리 (읽기만 함):
```sql
select
  (select pg_get_constraintdef(oid) like '%exec_upward%' from pg_constraint where conname = 'cases_stage_check') as "1 임원 상향 단계",
  (select count(*) from information_schema.columns where table_name = 'cycles' and column_name in ('mix_exec_upward','mix_exec_kpi','exec_upward_member','exec_upward_leader')) as "2 임원 비율 칸(4)",
  (select mix_leader_personal || '/' || mix_leader_kpi || '/' || mix_leader_upward from cycles where id = 1) as "2 팀장 비율",
  (select count(*) from information_schema.columns where table_name = 'final_results' and column_name = 'score_exec_upward') as "2 확정 칸(1)",
  (select string_agg(name || sort_order, ' ' order by sort_order) from positions) as "6 직급",
  (select pg_get_functiondef('public.rule_relations_base'::regproc) like '%exec_upward%') as "7 규칙",
  (select pg_get_functiondef('public.lock_cases'::regproc) like '%records_delete%') as "9 잠금",
  (select count(*) from pg_proc where proname = 'delete_evaluation_records') as "10 전체 삭제(1)";
```
- 안 바뀜: false / 0 / 20/30/50 / 0 / 직급 10개 / false / false / 0
- 011 완료: true / 4 / 20/40/40 / 1 / 직급 15개 / true / true / 1
- 어느 쪽이든 고친 011(score-v2)을 그대로 다시 실행하면 된다.

## 4. 지킬 것
- SQL은 Supabase SQL Editor에서 실행하고 **확인 쿼리를 꼭 돌린다**. "Success"만 믿지 않는다 (002·003 때 Success인데 안 들어간 적 있음).
- 관리용 열쇠(service_role)는 Supabase 화면 안에서만 본다. 코드·채팅(Claude 포함)·카톡·GitHub에 넣지 않는다. `.env.local`에만 두고, `VITE_` 이름을 붙이지 않는다.
- `.env.local` 줄 이름: `VITE_SUPABASE_URL`, `VITE_SUPABASE_ANON_KEY`, `SUPABASE_SERVICE_ROLE_KEY`
- 실제 직원 정보·시험 SQL 파일은 저장소에 넣지 않는다. `pnpm format`은 쓰지 않는다.
