중간 적용 여부 확인 쿼리 (읽기만 함):
```sql
select
  (select pg_get_constraintdef(oid) like '%exec_upward%' from pg_constraint where conname = 'cases_stage_check') as "1 임원 상향 단계",
  (select count(*) from information_schema.columns where table_name = 'cycles' and column_name in ('mix_exec_upward','mix_exec_kpi','exec_upward_member','exec_upward_leader')) as "2 임원 비율 칸(4)",
  (select mix_leader_personal || '/' || mix_leader_kpi || '/' || mix_leader_upward from cycles where id = 1) as "2 팀장 비율",
  (select count(*) from information_schema.columns where table_name = 'final_results' and column_name = 'score_exec_upward') as "2 확정 칸(1)",
  (select string_agg(name || sort_order, ' ' order by sort_order) from positions) as "6 직급",
  (select pg_get_functiondef('public.rule_relations_base'::regproc) like '%exec_upward%') as "7 규칙",
  (select pg_get_functiondef('public.lock_cases'::regproc) like '%records_delete%') as "9 잠금",
  (select count(*) from pg_proc where proname = 'delete_evaluation_records') as "10 전체 삭제(1)";
```

- 011 완료: true / 4 / 20/40/40 / 1 / 직급 15개 / true / true / 1
- 어느 쪽이든 고친 011(score-v2)을 그대로 다시 실행하면 된다.

## 4. 지킬 것
- SQL은 Supabase SQL Editor에서 실행하고 **확인 쿼리를 꼭 돌린다**. "Success"만 믿지 않는다 (002·003 때 Success인데 안 들어간 적 있음).
- 관리용 열쇠(service_role)는 Supabase 화면 안에서만 본다. 코드·채팅(Claude 포함)·카톡·GitHub에 넣지 않는다. `.env.local`에만 두고, `VITE_` 이름을 붙이지 않는다.
- `.env.local` 줄 이름: `VITE_SUPABASE_URL`, `VITE_SUPABASE_ANON_KEY`, `SUPABASE_SERVICE_ROLE_KEY`
- 실제 직원 정보·시험 SQL 파일은 저장소에 넣지 않는다. `pnpm format`은 쓰지 않는다.

## 5. 공통 연결 파일 사용법 (src/lib/admin-data.ts, 강영주)
관리자 화면이 저장소(Supabase)를 읽고 쓰는 공통 파일. 페이지마다 따로 만들지 말고 이것을 불러다 쓴다.
점수 계산은 하지 않는다 (src/lib/scoring.ts가 함). 공개용 열쇠 + 관리자 로그인으로만 읽힌다.

| 함수 | 하는 일 | 돌려주는 값 |
|---|---|---|
| `isAdminSession()` | 실제 관리자로 로그인했는지. 역할 미리보기(가짜 로그인)면 false | `true` / `false` |
| `loadCurrentCycle()` | 지금 회차: **평가 중인 회차, 없으면 번호가 가장 큰 회차** | `AdminCycle` 또는 `null`(회차 없음) |
| `loadScoreData(회차)` | 그 회차의 직원·부서·제출된 평가 건·문항·답·보정 기록·종합 의견을 한 번에 읽는다 | `ScoreData` |
| `scoreResultsOf(자료)` | `loadScoreData` 결과로 직원별 점수 계산 (`computeResults(자료.input)`과 같음) | `ScoreResult[]` |

`AdminCycle` 칸: `id` 회차 번호 · `name` 이름 · `status` before 평가 전 / in_progress 평가 중 / done 평가 완료 · `startDate`·`deadline` 시작일·마감일(미정이면 null) · `resultPublished`·`publishedAt` 결과 확정 · `weights` 단계 비율 · `mix` 최종 점수 비율

`ScoreData` 칸: `cycle` · `people`(직원, 내부 번호 `id` 포함) · `departments`(KPI 없으면 null) · `input`(scoring.ts에 그대로 넘기는 값) · `answerData`(제출된 평가 건·문항·답) · `opinions`(받은 평가의 종합 의견, 평가자 없음)

페이지에서 쓰는 예:
```ts
import { isAdminSession, loadCurrentCycle, loadScoreData, scoreResultsOf } from "@/lib/admin-data"

if (await isAdminSession()) {              // 역할 미리보기면 가짜 데이터를 쓴다
  const cycle = await loadCurrentCycle()   // 회차가 없으면 null
  if (cycle) {
    const data = await loadScoreData(cycle)
    const results = scoreResultsOf(data)   // 직원별 단계 점수·개인 평가·최종 점수
  }
}
```
- 비율·KPI를 바꿔 보며 미리 계산할 때는 `computeResults({ ...data.input, weights, mix })`처럼 칸만 바꿔 넣는다 (scoring.ts).
- 오류는 `throw`로 알린다. 화면에서는 `caught.message`를 그대로 보여 주면 된다.
  - 권한 규칙에 막히면: "권한이 없습니다. 관리자로 로그인했는지 확인해 주세요." (우회하지 않는다)
  - `.env.local`이 없으면: "저장소 설정(.env.local)이 없어 불러올 수 없습니다."
  - 저장했는데 바뀐 줄이 없으면(권한 규칙이 조용히 막은 경우): "○○이(가) 저장되지 않았습니다. 관리자로 다시 로그인해 주세요."
- 같은 파일의 다른 함수: 확정 결과 읽기 `loadFinalResults`, 결과 확정·취소 `publishResults`·`unpublishResults`, 건의함 `loadSuggestions`, 저장 `saveCycleRatios`·`saveDepartmentKpi`·`insertAdjustments`

점수 재료를 만드는 규칙 (scoring.ts 아래층 `stageFieldScoresFromAnswers`, `loadScoreData` 안에서 쓴다):
- 평가 내용 점수 = 객관식 답(1~5) 평균 × 배점 ÷ 5. 분야 점수 = 그 분야 평가 내용 점수의 합 (소수 첫째 자리)
- 서술형 점수 = 바로 위 평가자(팀원 → 팀장 평가, 팀장 → 임원 평가)의 점수 하나. 자기·팀장·임원 단계에 똑같이 더한다. 자기 점수는 참고용
- "제출"된 평가 건만 쓴다. 상향 = 제출한 사람들의 분야별 평균, 임원 상향 = 평가자 역할(팀원·팀장)별 평균
