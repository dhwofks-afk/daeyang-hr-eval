# 평가 작성 (참여자) — 담당: 박수빈
기한: 11/1 화면(가짜 데이터) → 11/4 실제 데이터 연결

**우선순위: 이 페이지가 대시보드보다 먼저다.** 발표 1~3번 장면이 이 화면에서 시작한다.

## 0. 목표
발표 1~3번 장면: 팀원이 로그인해서 자기평가를 쓰고 제출 → 팀장이 팀원의 자기평가를 보면서 점수를 매기고 제출 → 임원이 제출.
이 화면에서 만든 답이 점수·보정, 대시보드, 리포트의 재료가 된다.

## 1. 페이지·폴더
| 주소 | 폴더 | 이번 범위 |
|---|---|---|
| /my/evaluations | my-evaluations | ✅ 내 평가 목록 (이미 있는 페이지 → CSS 클래스 이름에 페이지 이름 붙이기부터) |
| /my/evaluations?case=번호 | my-evaluations (같은 폴더) | ✅ 평가 작성 화면 (같은 주소에 ?case=번호. routes.tsx는 고치지 않음) |

## 2. 화면 구성

### 내 평가 목록 (/my/evaluations)
- 내가 해야 할 평가 건을 카드로 보여 준다
  | 역할 | 보이는 카드 |
  |---|---|
  | 팀원 | 자기평가 1 + 내 팀장 상향평가 1 + 같은 본부 임원 임원상향평가 1 |
  | 팀장 | 자기평가 1 + 팀원 평가(팀장평가) n + 같은 본부 임원 임원상향평가 1 |
  | 임원 | 배정된 대상 임원평가 n (임원은 자기평가 없음. 임원 본인은 임원상향평가를 받는다) |
- 카드에 보이는 것: 대상 이름·부서·직급, 단계, 상태(작성 전 / 작성 중 / 제출 / 반려), 마감(미정이면 "미정")
- 팀장·임원 카드에는 대상의 **전 단계 완료 여부** 표시 (예: "자기평가 제출 완료 ✓")
- 반려된 건은 맨 위에, 눈에 띄게 ("반려된 평가" 묶음)
- 나머지는 묶음 제목으로 나눈다: 자기평가 / 상향평가 (임원) / 상향평가 (팀장) (임원이 보면 하향평가 (팀장)) / 하향평가 (팀원). 묶음 안은 직급이 높은 순서
- 팀장·임원 목록에는 이름 검색 + 상태 필터. [평가하기]를 누르면 안내 팝업(평가 안내 → 작성 전 확인)을 거쳐 작성 화면으로 간다

### 평가 작성 (/my/evaluations?case=번호)
1. 위쪽: 대상 이름·부서·직급, 단계, 상태, 진행률(답한 문항 / 전체)
2. 상향평가·임원상향평가일 때: "작성자는 관리자만 볼 수 있습니다" 안내
3. 문항: 대상의 역할로 정해진 문항 세트 (상향평가·임원상향평가는 상향 세트)
   - 구분 → 평가 내용 순서로 묶어서 보여 준다 (평가표와 같은 순서, 배점은 평가 내용마다)
   - 팀장·상향 평가표는 구분마다 문항 1개(5문항). 문항이 평가 내용과 같은 문장이면 평가 내용 제목은 빼고 문항에서 한 번만 보여 준다
   - 객관식: 1~5 숫자 버튼 5개 (크게, 휴대폰에서 누르기 쉽게). 아래 "1 매우 미흡 · 5 매우 우수"
4. 서술형 (단계에 따라 다름)
   | 단계 | 화면 |
   |---|---|
   | 자기평가 | 서술 입력 + 자기 점수 입력 (0 ~ 배점). 입력 칸 안에 작성 예시 문구 |
   | 바로 위 평가자 (팀원 → 팀장, 팀장 → 임원) | 대상의 서술 내용과 자기 점수를 보여 주고, 최종 점수 입력 (0 ~ 배점) |
   | 그 밖의 평가자 (예: 팀원에 대한 임원) | 대상의 서술 내용만 읽기 (점수 입력 없음) |
5. 종합 의견 (자기평가엔 없음, 그 외 필수, 한 줄 이상)
6. [임시 저장] [제출] 버튼

## 3. 동작
- [임시 저장] → 상태 "작성 중", 지금까지 답 저장
- [제출] → 아래를 모두 확인한 뒤 확인 창 "제출하면 수정할 수 없습니다"
  - 모든 문항에 답했는지 (평가 내용은 모두 필수)
  - 종합 의견이 있는지 (자기평가 제외)
  - 빠진 곳이 있으면 제출하지 않고 그 문항으로 이동해서 표시
- 제출 후: 상태 "제출", 화면은 읽기 전용
- 반려된 건: 모든 문항을 다시 수정·제출. 화면 위에 "관리자가 반려했습니다 … 반려된 날부터 3일 안에 다시 제출해 주세요" + 반려 사유 표시 (남은 날·기한 지남은 관리자 반려 현황에만)
- 서술형 점수는 "바로 위 평가자"의 점수만 최종 계산에 쓰인다 (10-데이터설계 계산 규칙 2). 이 화면은 입력만 하고 계산하지 않는다

## 6. 하지 않을 것
- 건의사항, 만족도 설문 (이번 범위 밖 → 12-평가작성추가)
- 점수 계산 (scoring.ts가 함)
- 문항 편집
- 마감일 지나면 막기 (마감일 미정)
- 대시보드 숫자 계산 (04-대시보드에서)

## 7. 완료 체크리스트
- [ ] CSS 클래스 이름에 페이지 이름이 붙었고, 이름 바꾸기 전후 목록 화면이 같다
- [ ] 역할별로 맞는 카드가 보인다 (팀원 3장, 팀장 2+n장, 임원 n장)
- [ ] 문항이 평가표 순서(구분 → 평가 내용)로 나온다
- [ ] 객관식 5개 버튼이 휴대폰 너비에서도 누르기 쉽다
- [ ] 자기평가 서술형에 서술 + 자기 점수 칸이 있고, 배점보다 큰 점수는 안 들어간다
- [ ] 팀장 화면에서 팀원의 서술 내용과 자기 점수가 보이고 최종 점수를 넣을 수 있다
- [ ] 임원이 팀원을 평가할 때 서술형은 읽기만 된다
- [ ] 빠진 문항이나 종합 의견(자기평가 제외)이 없으면 제출되지 않고 그 위치로 이동한다
- [ ] 제출 후 읽기 전용이 되고 목록 카드 상태가 "제출"로 바뀐다
- [ ] 임시 저장 후 다시 들어오면 답이 남아 있다
- [ ] 상향 평가 화면에 익명 안내가 보인다
- [ ] pnpm build, pnpm exec tsc --noEmit 통과
