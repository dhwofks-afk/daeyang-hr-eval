# 배포 — 담당: 오재란
목표: main에 올릴 때마다 자동으로 최신이 되는 인터넷 링크 (Render, 11/3 Vercel에서 옮김)
주소: https://daeyang-hr-eval.onrender.com

## 0. 언제
- **가능한 한 빨리 한 번 배포한다** (11/4까지 미루지 않음). 처음 배포에서 나는 문제를 미리 찾기 위해서
- 이후엔 main에 합칠 때마다 자동으로 다시 배포된다. 링크 주소는 그대로

## 1. 배포 전에 저장소에 넣을 것 (오재란, 공통 파일)
| 파일 | 왜 |
|---|---|
| (확인) Edge Function import-employees의 CORS 설정 | 브라우저가 다른 주소(Render)에서 함수를 부를 수 있게 허용돼 있는지 |
| (확인) package.json packageManager = pnpm@10.34.3, Node 22 | Render가 같은 도구로 빌드하게 |

## 2. Render 설정 (본인이 웹에서)
1. render.com → GitHub로 로그인 → **New → Static Site** → daeyang-hr-eval 저장소, main 브랜치
2. 설정
   | 칸 | 값 |
   |---|---|
   | Build Command | pnpm install && pnpm build |
   | Publish Directory | dist |
3. **Redirects/Rewrites**: Source `/*` → Destination `/index.html`, Action **Rewrite** (새로고침 404 막기)
4. **Environment** (환경 변수 2개)
   | 이름 | 값 |
   |---|---|
   | VITE_SUPABASE_URL | .env.local 첫째 줄 값 |
   | VITE_SUPABASE_ANON_KEY | .env.local 둘째 줄 값 (공개용 sb_publishable_) |
   - **관리용 열쇠(SUPABASE_SERVICE_ROLE_KEY)는 절대 넣지 않는다.** 화면은 공개용 열쇠만 쓴다
5. 저장하면 배포 → https://daeyang-hr-eval.onrender.com

## 3. Supabase 설정 (본인이 웹에서)
- Authentication → URL Configuration → **Site URL**에 Render 링크 넣기 (이름+사번 로그인은 이동 주소를 쓰지 않지만 맞춰 둔다)
- 발표 전날 한 번 접속 (무료 프로젝트는 1주일 쉬면 멈춤)

## 4. 배포 후 확인 체크리스트
- [ ] 링크가 열리고 로그인 화면이 보인다
- [ ] 김민수 / 900011 로그인 → 평가 목록, 상단바 "김민수 / 팀원"
- [ ] 관리자 로그인 → 대시보드
- [ ] /admin/scores/kpi 에서 **새로고침해도 404가 안 난다** (Render Rewrite 확인)
- [ ] 평가 관계 화면이 실제 데이터를 읽는다 (Supabase 연결 확인)
- [ ] 데이터 관리에서 양식 내려받기·명단 미리보기까지 된다 (적용은 하지 않음. Edge Function 호출은 시험 CSV로만, 하면 정리 SQL)
- [ ] 휴대폰으로 링크를 열어 로그인·평가 목록이 보인다 (이제 실제 휴대폰 확인 가능)
- [ ] 브라우저 개발자 도구 콘솔에 오류가 없다
- [ ] 페이지 소스에 noindex가 있고 /robots.txt가 검색을 막는다
- [ ] 빌드 결과에 관리용 열쇠가 없다 (Claude Code로 검색)

## 5. 알아 둘 것
- **main 합치기**: pnpm build와 pnpm exec tsc --noEmit이 통과한 것만 합친다 (docs/15-작업규칙.md)
- **고친 내용은 바로 실제 화면에 나간다**: 확인 후 합치기를 지키고, 평가 기간 중 큰 수정은 피한다
- 화면 코드가 500kB를 조금 넘는다는 빌드 경고는 무시해도 된다

## 6. 시연 직전 순서 (11/4 리허설, 11/5 발표)
1. main 최종 합치기 → Render 자동 배포 완료 확인
2. SQL Editor에서 90_demo_reset.sql → 파일 끝 검사 결과 확인 (평가 1개 · 평가 건 127 · 제출 119 · 작성 전 8)
3. 링크로 시연 흐름 한 바퀴 (평가 관계 → 평가 시작 → 김민수 → 박서준 → 이정호 → 진행 현황 → 비율·KPI·보정 → 결과 확정 → 개인 리포트(임원 포함))
4. 리허설 후 다시 90 실행
5. 발표 당일 아침 링크 한 번 열어 두기

## 7. 문제가 생기면
| 증상 | 원인·해결 |
|---|---|
| 빌드 실패 | Render의 빌드 기록(해당 서비스 → Events/Logs)의 빨간 줄을 Claude Code에 붙여 넣기 |
| 로그인 시 "저장소 설정이 없어" | Render 환경 변수 이름·값 확인 후 **Manual Deploy** (환경 변수는 다시 배포해야 반영) |
| 새로고침하면 404 | Render Redirects/Rewrites의 /* → /index.html Rewrite 확인 |
| 명단 적용에서 오류 (CORS) | Edge Function의 허용 주소 설정 |
| 데이터가 안 나옴 | Supabase 일시정지 여부, 환경 변수 주소 |

## 8. 인계 때
- 회사 명의 Render(또는 다른 배포처)에서 회사 GitHub 저장소를 Import → 환경 변수는 회사 Supabase 값으로
