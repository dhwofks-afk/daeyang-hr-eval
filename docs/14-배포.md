# 배포 — 담당: 오재란
목표: main에 올릴 때마다 자동으로 최신이 되는 인터넷 링크 (Vercel 무료)

## 0. 언제
- **가능한 한 빨리 한 번 배포한다** (11/4까지 미루지 않음). 처음 배포에서 나는 문제를 미리 찾기 위해서
- 이후엔 main에 합칠 때마다 자동으로 다시 배포된다. 링크 주소는 그대로

## 1. 배포 전에 저장소에 넣을 것 (오재란, 공통 파일)
| 파일 | 왜 |
|---|---|
| vercel.json (새 파일) | 주소 되돌림 설정. /admin/scores/kpi 같은 주소에서 새로고침하면 Vercel이 그 파일을 못 찾아 404가 나기 때문에, 모든 주소를 index.html로 보내게 한다 |
| (확인) Edge Function import-employees의 CORS 설정 | 브라우저가 다른 주소(Vercel)에서 함수를 부를 수 있게 허용돼 있는지 |
| (확인) package.json packageManager = pnpm@10.34.3, Node 22 | Vercel이 같은 도구로 빌드하게 |

## 2. Vercel 설정 (본인이 웹에서)
1. vercel.com → **GitHub로 로그인** (Hobby 무료)
2. **Add New → Project** → GitHub 저장소 목록에서 daeyang-hr-eval → **Import**
   - 비공개 저장소가 안 보이면 "Adjust GitHub App Permissions"에서 이 저장소 접근 허용
3. 설정
   | 칸 | 값 |
   |---|---|
   | Framework Preset | Vite |
   | Build Command | pnpm build |
   | Output Directory | dist |
   | Node.js Version | 22 (Settings → General) |
4. **Environment Variables** (Production·Preview 둘 다)
   | 이름 | 값 |
   |---|---|
   | VITE_SUPABASE_URL | .env.local 첫째 줄 값 |
   | VITE_SUPABASE_ANON_KEY | .env.local 둘째 줄 값 (공개용 sb_publishable_) |
   - **관리용 열쇠(SUPABASE_SERVICE_ROLE_KEY)는 절대 넣지 않는다.** 화면은 공개용 열쇠만 쓴다
5. **Deploy** → 몇 분 뒤 `https://(이름).vercel.app` 링크

## 3. Supabase 설정 (본인이 웹에서)
- Authentication → URL Configuration → **Site URL**에 Vercel 링크 넣기 (이름+사번 로그인은 이동 주소를 쓰지 않지만 맞춰 둔다)
- 발표 전날 한 번 접속 (무료 프로젝트는 1주일 쉬면 멈춤)

## 4. 배포 후 확인 체크리스트
- [ ] 링크가 열리고 로그인 화면이 보인다
- [ ] 김민수 / 900011 로그인 → 평가 목록, 상단바 "김민수 / 팀원"
- [ ] 관리자 로그인 → 대시보드
- [ ] /admin/scores/kpi 에서 **새로고침해도 404가 안 난다** (vercel.json 확인)
- [ ] 평가 관계 화면이 실제 데이터를 읽는다 (Supabase 연결 확인)
- [ ] 데이터 관리에서 양식 내려받기·명단 미리보기까지 된다 (적용은 하지 않음. Edge Function 호출은 시험 CSV로만, 하면 정리 SQL)
- [ ] 휴대폰으로 링크를 열어 로그인·평가 목록이 보인다 (이제 실제 휴대폰 확인 가능)
- [ ] 브라우저 개발자 도구 콘솔에 오류가 없다
- [ ] 페이지 소스에 noindex가 있고 /robots.txt가 검색을 막는다
- [ ] 빌드 결과에 관리용 열쇠가 없다 (Claude Code로 검색)

## 5. 알아 둘 것
- **미리보기 링크**: 브랜치마다 Vercel이 따로 링크를 만든다. 기본으로 Vercel 로그인한 사람만 볼 수 있게 보호된다
- **약관**: Vercel 무료(Hobby)는 비상업·개인 용도. 강의 시연까지는 우리 계정, 인계 때 회사 계정(유료 또는 다른 배포처)으로 옮긴다
- **고친 내용은 바로 실제 화면에 나간다**: 확인 후 합치기를 지키고, 평가 기간 중 큰 수정은 피한다
- 화면 코드가 500kB를 조금 넘는다는 빌드 경고는 무시해도 된다

## 6. 시연 직전 순서 (11/4 리허설, 11/5 발표)
1. main 최종 합치기 → Vercel 자동 배포 완료 확인
2. SQL Editor에서 90_demo_reset.sql → 확인 쿼리 (before · false / 96 / 6)
3. 링크로 시연 흐름 한 바퀴 (평가 관계 → 평가 시작 → 김민수 → 박서준 → 이정호 → 진행 현황 → KPI·보정·등급 → 결과 공개 → 내 결과)
4. 리허설 후 다시 90 실행
5. 발표 당일 아침 링크 한 번 열어 두기

## 7. 문제가 생기면
| 증상 | 원인·해결 |
|---|---|
| 빌드 실패 | Vercel의 빌드 기록(Deployments → 해당 배포 → Build Logs)의 빨간 줄을 Claude Code에 붙여 넣기 |
| 로그인 시 "저장소 설정이 없어" | Vercel 환경 변수 이름·값 확인 후 **Redeploy** (환경 변수는 다시 배포해야 반영) |
| 새로고침하면 404 | vercel.json 확인 |
| 명단 적용에서 오류 (CORS) | Edge Function의 허용 주소 설정 |
| 데이터가 안 나옴 | Supabase 일시정지 여부, 환경 변수 주소 |

## 8. 인계 때
