## 2. 표 만들기
- 10-데이터설계 8개 표를 그대로 만든다.
- 직원 표에 칸 하나 추가: 로그인 계정 (Supabase 로그인 기능의 계정과 연결)

  이 표시는 서버(계정 만들기 스크립트)에서만 붙일 수 있어 직원이 스스로 관리자가 될 수 없다.

## 3. 처음 넣을 데이터
- 부서 3개, 회차 1개 (src/data/scores.ts의 설정값 그대로)
- 직원 28명 (src/data/people.ts 27명 + 임원 1명) + 직군·평가 제외·재직 상태 칸 채우기
- 문항: 회사 인사평가표 5종(빈 양식 PDF)을 그대로 옮긴다
  - 관리직-팀원 / 관리직-팀장 / 생산직-팀원 / 생산직-팀장 / 상향(팀장평가표)
  - 분야 · 평정요소 · 평정요소 배점 · 문구 · 유형(객관식/서술형) · 순서
  - 문항 세트마다 배점 합이 100인지 확인
  - 2023 인사평가 공고는 실명이 있어 넣지 않는다
- 평가 건: 아래 규칙으로 만든다
  - 모든 직원: 자기평가 1건
  - 팀원: 같은 부서 팀장의 팀장 평가 1건 + 임원 평가 1건
  - 팀장: 임원 평가 1건 + 같은 부서 팀원 각자의 상향 평가
  - 평가 제외·퇴사자는 만들지 않는다
- 시연용 답: 대부분의 평가 건은 답을 미리 채워 "제출" 상태로 둔다 (점수 분포는 scores.ts와 비슷하게).
  시연에 쓸 2~3명의 평가 건은 비워 두어 발표 중 실제로 제출한다.

## 4. 로그인
### 방식: Supabase 로그인 기능을 빌려 쓴다
- 직원마다 로그인 계정을 미리 만들어 둔다 (scripts/create-accounts)
  - 계정 아이디: 사번으로 만든 내부용 메일 (예: 900001@daeyang-hr.local, 실제 메일 아님)
  - 계정 비밀번호: 사번. Supabase 최소 6자리 규칙 때문에 시스템 안에서만 앞에 0을 채워 6자리로 맞춘다
- 로그인 화면은 이름 + 사번만 받는다
  1. 사번으로 계정 로그인
  2. 서버 함수로 그 계정의 이름이 입력한 이름과 같은지 확인
  3. 다르면 바로 로그아웃하고 "이름 또는 사번이 맞지 않습니다" (어느 쪽이 틀렸는지 알려 주지 않음)
- 로그인 후 역할(팀원·팀장·임원·관리자)에 따라 첫 페이지로 이동 (골격 그대로)
- 로그인 화면의 "역할 미리보기"는 이 단계에서 제거한다 (CLAUDE.md 4번)
- 관리자: 같은 방식으로 별도 계정 하나 + 별도 비밀번호 (사번 아님)
- Supabase 설정에서 "스스로 가입하기(sign up)"를 끈다. 계정은 스크립트로만 만든다

## 5. 권한 규칙 (RLS)
기본은 모든 표 잠금 (프로젝트 만들 때 자동 RLS 켬). 아래만 연다.

| 표 | 직원(팀원·팀장·임원) | 관리자 |
|---|---|---|
| 직원 | 직접 못 읽음. 아래 "내 평가 대상 목록"으로만 | 전체 읽기·쓰기 |
| 부서 · 평가 설정 · 문항 | 읽기만 | 읽기·쓰기 |
| 평가 건 | 내가 평가자인 건만. 제출할 때 상태·의견만 바꿈 (평가자·대상은 못 바꿈) | 전체. 반려 가능 |
| 답 | 내 평가 건의 답만 쓰기. 제출 후엔 못 고침 (반려되면 다시 가능) | 전체 읽기 |
| 답 (예외) | 평가자는 대상의 자기평가 답을 읽을 수 있음 (서술형 점수를 정하려면 필요) | — |
| 상향 평가 | 팀원은 자기가 쓴 것만. 팀장은 자기에 대한 상향 평가를 못 봄 | 전체 (평가자 신원 포함) |
| 보정 기록 | 못 봄 | 읽기 + 새 줄 추가만 (고치기·지우기 불가) |
| 확정 결과 | 직접 못 읽음. "내 결과 가져오기" 서버 함수로만 | 전체 |

### 내 평가 대상 목록 (사번 없음)
| 역할 | 보이는 사람 | 보이는 칸 |
|---|---|---|
| 팀원 | 나 + 상향 평가할 내 팀장 | 이름·부서·직급 |
| 팀장 | 나 + 내 팀원들 | 이름·부서·직급·진행 여부 |
| 임원 | 나 + 배정된 평가 대상 | 이름·부서·직급·진행 여부 |
- 사번은 어떤 직원 화면에도 나오지 않는다 (사번 = 비밀번호)

### 내 결과 가져오기 (서버 함수)
1. 결과가 공개됐는지 확인
2. 로그인한 본인 줄만
3. 공개 범위에 체크된 칸만 돌려준다
- 공개 범위는 칸 단위라 권한 규칙(줄 단위)으로는 숨길 수 없어서 함수로 처리한다

## 6. 열쇠 다루기
| 열쇠 | 어디에 | 비고 |
|---|---|---|
| 프로젝트 주소 (Project URL) | .env.local의 VITE_SUPABASE_URL | 화면에서 씀 |
| 공개용 열쇠 (anon / publishable) | .env.local의 VITE_SUPABASE_ANON_KEY | 브라우저에 보여도 되도록 만든 열쇠. 안전은 5번 권한 규칙이 지킴 |
| 관리용 열쇠 (service_role / secret) | .env.local의 SUPABASE_SERVICE_ROLE_KEY | 계정 만들기 스크립트에서만. **VITE_ 를 붙이지 않는다** (붙이면 화면에 노출됨) |
| 데이터베이스 비밀번호 | 코드에 안 씀 | 본인만 보관 |
| 관리자 계정 비밀번호 | 스크립트 실행 때 직접 입력 | 파일에 저장하지 않음 |
- .env.local이 Git에서 빠지는지 확인한다
- 팀원에게는 주소와 공개용 열쇠만, GitHub이 아닌 개인 메시지로 전달한다
- 관리용 열쇠는 본인 컴퓨터 밖으로 내보내지 않는다 (카톡·GitHub·Claude 채팅 모두 금지)
- 배포(Vercel)에는 주소와 공개용 열쇠만 넣는다
