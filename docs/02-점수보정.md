## 0. 목표
발표 5번 장면: 제출된 평가가 가중 합산되고(개인 평가) → 부서 KPI·상향 평가와 비율로 섞이고 → 필요하면 최종 점수를 보정한다. (등급 없음, 11/2 차장님 답변)
특히 "KPI나 보정을 바꾸면 최종 점수가 바로 바뀌는 장면"을 보여 준다. (부서 성과 연동형 = 프로젝트 핵심)

점수 순서: 개인 평가(가중 합산) → 비율로 섞기(팀원 개인 80 + KPI 20 / 팀장 개인 20 + KPI 40 + 상향 40 / 임원 임원상향 40 + KPI 60) → 최종 점수 보정(선택)
(임원상향 = 팀원 평균 50 + 팀장 평균 50 / 본부 임원의 KPI = 본부 부서 KPI 평균)

## 2. 화면 구성

### 평가 결과 (/admin/scores/results)
1. 위쪽 요약: 회차 이름, 상태, 제출 현황(단계, 제출 n / 전체 n). 상단바 평가 선택 상자에서 고른 평가 기준
2. 비율: 팀원·팀장·임원 카드 3개. 카드마다 개인 평가 비율(임원은 임원상향평가: 팀원 평균·팀장 평균) + 최종 점수 비율(팀원 개인·KPI / 팀장 개인·KPI·상향 / 임원 임원상향·KPI)
   - 묶음마다 "= 합계 ✓/✗" 표시, 합계 100이 아니면 저장 안 됨, 결과 확정 후 잠금
   - [기본값으로] → 11/3 결정 비율을 칸에 넣기만 한다 / [비율 저장] → 아래 표가 새 비율로 다시 계산된다
3. 부서 선택: 전체 + 부서 6개(경영기획부·기술영업부·생산부·기술부·구매자재부·안전품질부) + 이름 검색 + 정렬 기준 선택: 부서·순위(기본) / 최종 점수 / 이름
4. 결과 표 (기본: 부서 → 순위 순)
   이름 · 부서 · 직급 · 역할 · 자기평가 · 팀장평가 · 임원평가 · 상향평가 · 임원상향평가 · 개인 평가 · 비율 반영 · 최종
   - 미제출 단계는 "미제출(0)"로 빨간 표시, 받지 않는 단계는 "—"
   - 비율 반영 점수 옆에 개인 평가 대비 +/− 표시 (예: 80.4 → 82.3 ▲1.9)
   - 보정된 사람은 최종 점수 옆에 "보정" 표시

### KPI 반영 (/admin/scores/kpi)
1. 안내 문구만: 섞는 비율은 평가 결과 화면에서 정한다 (반영 방법 카드·가산·배율·기준값·계수 없음)
2. 부서별 KPI 입력 표: 부서명 · 인원 · KPI 점수(입력, 0~100) · 개인 평가 평균 · KPI 반영 후 평균 (입력값이 바뀌면 바로 바뀜)
3. [저장] 버튼

### 최종 점수 보정 (/admin/scores/adjust)
1. 부서 선택 + 이름 검색 + 정렬 기준 선택: 부서·순위(기본) / 최종 점수 / 이름
2. 보정 표 (기본: 부서 → 순위 순). 여러 명을 체크하고 "체크한 n명에게 한 번에" 칸에 보정 점수·사유를 적어 [넣기] → [저장]
   체크 · 이름 · 부서 · 비율 반영 점수 · 보정 점수(입력, 비우면 보정 없음) · 사유(선택) · 최종 점수
   - 한 화면에서 보정 전·후를 나란히 비교
   - 보정한 줄은 색으로 표시
3. (등급 비율 없음)
4. [저장] 버튼
5. 보정 기록: 누가 · 언제 · 누구를 · 몇 점 → 몇 점(또는 보정 취소) · 사유

## 3. 동작
- KPI [저장] → 그 평가의 부서 KPI 표(cycle_kpis, 016)에 저장되고, 평가 결과 표가 새 값으로 다시 계산된다.
- 보정 [저장] → 최종 점수가 바뀐다. 보정 기록에 사람마다 한 줄 쌓인다 (지우거나 고칠 수 없음). 보정 점수를 비우고 저장하면 "보정 취소" 줄이 쌓인다.
- 점수는 저장하지 않고 scoring.ts로 그때그때 계산한다.
- [비율 저장] → 평가 설정에 저장되고, 평가 결과 표가 새 값으로 다시 계산된다.
- "결과 확정" 후에는 비율·KPI·보정을 바꿀 수 없다. 화면에 "결과 확정됨 · 수정 불가" 표시.

### 11/1까지 (가짜 데이터)
- src/data/scores.ts 새 파일에 위 표와 같은 칸 이름으로 가짜 데이터를 만든다.
- 직원 30명은 src/data/people.ts를 그대로 쓴다 (읽기만).
- 평가 건·답까지 가짜로 만들긴 너무 크므로, 직원별 단계 점수(자기·팀장·임원·상향)를 바로 넣어 시작한다.
- 가짜 단계 점수는 회사 평가표의 배점 구조에 맞춰 구분별로 만든다.
  - 팀원: 업무성과 35 / 능력 20 / 근무태도 20 / 보안·규정 10 / 조직문화 15
  - 팀장: 업무성과 30 / 리더십 및 조직관리 25 / 직무역량 및 의사결정 20 / 책임감 및 규정준수 15 / 협업 및 조직기여 10 (11/4 새 평가표, 서술형 없음)
- 실제 문항 데이터는 05-서버기반에서 공통 파일로 만든다.
- scoring.ts는 두 층으로 나눈다.
  - 아래층: 답 → 단계 점수 (11/4 실제 연결 때 사용)
  - 위층: 단계 점수 → 개인 평가 → 비율로 섞기 → 보정 (11/1부터 가짜 데이터로 사용)

## 7. 완료 체크리스트

### 계산 (scoring.ts)
- [ ] 팀원 개인 80.4, 부서 KPI 90 → 82.3 / 팀장 개인 78, KPI 90, 상향 85 → 85.6 / 임원 상향 85, KPI 90 → 88
- [ ] KPI가 개인 평가보다 낮은 부서는 점수가 내려간다
- [ ] 본부 임원의 KPI는 본부 부서 KPI 평균이다
- [ ] 결과가 0 아래, 100 위로 나가지 않는다
- [ ] 상향 미제출은 0점으로 섞인다
- [ ] 보정 점수가 있으면 그 값이 최종 점수다

### 화면
- [ ] 비율을 바꾸고 [비율 저장]하면 평가 결과 표가 다시 계산된다
- [ ] 묶음 합계가 100이 아니면 ✗ 표시가 나오고 저장되지 않는다
- [ ] KPI 값을 바꾸고 저장하면 평가 결과 표의 최종 점수가 바뀐다
- [ ] KPI 화면의 "KPI 반영 후 평균"이 입력값대로 바로 바뀐다
- [ ] 보정하면 최종 점수가 바뀌고, 보정 기록에 한 줄 생긴다
- [ ] 여러 명을 체크해 [넣기] → [저장]하면 한 번에 보정되고 기록이 사람마다 생긴다
- [ ] [기본값으로]를 누르면 11/3 결정 비율이 칸에 들어간다 (저장은 [비율 저장])
- [ ] 가짜 데이터에서 "결과 확정"을 켜면 비율·KPI·보정이 잠긴다
- [ ] 두 표(평가 결과·보정)에서 정렬 기준 3가지가 동작한다
- [ ] 이름 검색이 부서 선택과 함께 걸린다
- [ ] 점수는 모두 숫자로 표시된다
