## 1. 설치 (처음 한 번)

### Node.js 22
- nodejs.org → 버전 v22.x LTS 선택 → "Windows 설치 프로그램(.msi)" 다운로드
- 위쪽의 Docker·npm 선택 칸은 무시. 아래 .msi 파일만 받으면 됨
- 기본 옵션으로 설치

### pnpm
- 시작 메뉴에서 PowerShell 오른쪽 클릭 → "관리자 권한으로 실행"
  (창 위치가 C:\WINDOWS\system32 로 나오면 관리자 권한이 맞음)
- 아래 한 줄 실행 후 창 닫기
  ```
  corepack enable pnpm
  ```
- 버전은 프로젝트에 10.34.3으로 고정되어 있어 따로 맞출 필요 없음

### Git
- git-scm.com → Windows용 설치 파일
- 설치 중 두 곳만 바꾸기
  - 기본 편집기: Notepad
  - 기본 브랜치 이름: Override → main
- 나머지는 Next. 마지막 화면 체크박스 2개는 해제하고 Finish
- 옵션을 놓쳤다면 설치 후 Claude Code에게 아래 두 명령을 실행해 달라고 하면 됨
  ```
  git config --global init.defaultBranch main
  git config --global core.editor notepad
  ```

### 설치 후
- Claude Code 앱을 껐다 켜기 (새 프로그램 인식)

## 2. 코드 받기 (처음 한 번)

### 먼저 알아 둘 원리
- 코드 = 레시피, GitHub = 레시피 보관 책장, pnpm dev = 내 부엌에서 요리하기
- 각자 GitHub에서 코드를 받아 **자기 컴퓨터에서** pnpm dev를 켜고 http://localhost:8443 으로 본다.
- 주소는 셋 다 같지만, 보이는 화면은 **각자 컴퓨터의 코드**다.
  - 내가 고친 내용은 내 localhost에만 보인다.
  - PR이 main에 합쳐진 뒤 다른 사람이 최신본을 받아야(pull) 그 사람 화면에도 보인다.
- localhost는 내 컴퓨터에서만 열린다. 휴대폰·다른 사람은 접속할 수 없다.

### 1) 초대 수락
- GitHub 알림 또는 메일로 온 저장소 초대를 수락한다.

### 2) 코드 받기
- 코드를 둘 폴더를 정한다. OneDrive·구글 드라이브 같은 동기화 폴더는 피한다.
  (pnpm install 때 생기는 수만 개 파일이 동기화되면 느려지거나 오류가 날 수 있음)
- 그 폴더에서 Claude Code를 켜고 지시한다:
  "https://github.com/dhwofks-afk/daeyang-hr-eval 저장소를 이 폴더에 받아 줘(clone)."
- 처음이면 GitHub 로그인 창이 뜬다. 직접 로그인한다.
  - Claude Code가 로그인 창을 못 띄우고 실패하면 → 7번 "막혔을 때" 참고

### 3) 작성자 정보 (내 서명)
- 커밋할 때마다 "누가 저장했는지" 서명이 남는다. 처음 한 번 설정한다.
- 이메일은 GitHub 비공개용 이메일을 쓴다.
  GitHub → Settings → Emails → "숫자+아이디@users.noreply.github.com"
- Claude Code에 지시:
  "작성자 정보를 이 저장소에만 설정해 줘. 이름은 (내 GitHub 아이디), 이메일은 (비공개용 이메일)."

### 4) 실행
- Claude Code에 지시: "pnpm install 하고 pnpm dev로 개발 서버 켜 줘."
- 브라우저에서 http://localhost:8443 → 로그인 화면이 보이면 성공
- 로그인 화면의 "역할 미리보기"로 팀원·팀장·임원·관리자 화면을 모두 볼 수 있다.
- 컴퓨터를 껐다 켜면 개발 서버도 꺼진다. 다시 "pnpm dev 켜 줘"라고 하면 된다.

## 3. 작업 흐름 (매번)

### 한눈에
최신본 받기 → 내 브랜치 만들기 → 작업·세이브 → 올리기 → PR → (합쳐지면) 다음 작업

### 1) 최신본 받기
- 다른 사람이 합친 내용을 먼저 받아야 내 코드와 어긋나지 않는다.
- 지시: "main으로 이동해서 최신본 받아 줘(pull)."

### 2) 내 브랜치 만들기
- 브랜치 = 원본(main)을 건드리지 않는 내 작업 줄기
- 이름 규칙: page-(페이지 폴더 이름)   예) page-people-org-chart
- 지시: "page-people-org-chart 브랜치 만들어서 이동해 줘."

### 3) 작업하고 세이브(커밋)
- 지시: "docs/(내 페이지 문서).md 읽고 계획 먼저 보고해 줘. 파일은 아직 고치지 마."
- 계획을 읽고 괜찮으면 승인 → 결과 보고를 받으면 localhost에서 직접 화면 확인
- 확인되면 세이브. 작은 단위로 자주 하는 게 좋다.
  지시: "커밋해 줘. 메시지는 '조직도: (한 일)'."
- 커밋 메시지 형식: "페이지 이름: 한 일"   예) "조직도: 부서 목록 화면"

### 4) 올리기
- 지시: "내 브랜치를 GitHub에 올려 줘(push)."

### 5) PR 보내기 (GitHub 웹에서)
- 저장소 페이지에 노란 줄 "Compare & pull request" 버튼이 뜨면 클릭
  (안 뜨면 Pull requests 탭 → New pull request → 내 브랜치 선택)
- 제목: "조직도: (한 일)"
- 내용에 세 가지를 적는다
  1. 무엇을 만들었는지
  2. 어떻게 확인했는지 (pnpm build·tsc 결과, 확인한 화면)
  3. 공통 파일 변경이 필요하면 무엇을, 왜 (직접 고치지 말고 여기 적기)
- Create pull request

### 6) 합쳐진 뒤
- 공통 파일 담당자가 검토하고 main에 합친다. 수정 요청이 오면 같은 브랜치에서 고쳐 다시 올린다.
- 합쳐지면 1)부터 다시. 다음 작업은 새 브랜치로 한다.

### 작업 도중 main이 바뀌었다는 연락을 받으면
- PR 보내기 전에 지시: "최신 main을 받아서 내 브랜치에 반영해 줘. 충돌이 나면 고치지 말고 멈추고 알려 줘."

## 4. 꼭 지킬 규칙

### 내 페이지 폴더만
- 배정받은 src/pages/(내 페이지) 폴더 안의 파일만 고친다.
- 공통 파일은 고치지 않는다. 필요하면 PR 내용에 "무엇을, 왜"를 적어 요청한다.
  - 공통 파일: src/layout/, src/routes.tsx, src/data/, src/main.tsx,
    src/index.css의 공통 스타일, CLAUDE.md, package.json, pnpm-lock.yaml
- 예외 (CLAUDE.md에도 있음)
  - src/data/에 자기 페이지 전용 가짜 데이터를 새 파일로 추가 (예: src/data/org-chart.ts). 기존 data 파일은 고치지 않는다.
  - 새 페이지를 추가할 때 src/routes.tsx에 2줄 추가. 기존 줄은 고치지 않는다.
  - PR 내용에 "공통 파일 변경: (무엇)"으로 적는다.

### 개인정보
- 실제 직원 이름·사원번호·연락처를 코드, 가짜 데이터, 커밋, PR 어디에도 넣지 않는다.
- 회사에서 받은 자료(공고문, 평가표 등)에 실명이 있으면 Claude Code에 그대로 넣지 않는다.
  필요한 내용만 옮겨 적는다.

### main과 설치
- main에 직접 올리지 않는다. 항상 내 브랜치 → PR.
- 새 라이브러리 설치는 공통 파일 담당자에게 먼저 묻는다.
- 설치·실행은 pnpm만 쓴다. npm·yarn 명령을 직접 치지 않는다.

### 정해지지 않은 것
- 문서에 "회사 확인 중", "미정"이라고 적힌 것(점수 산식, 가중치 등)은 임의로 정하지 않는다.
  화면에는 "미정" 또는 빈칸으로 두고 공통 파일 담당자에게 알린다.

### 확인
- AI가 "완료했다"고 해도 localhost에서 직접 화면을 보고 나서 커밋·PR 한다.
- 개발 서버는 내 컴퓨터에서만 연다. 휴대폰 확인은 브라우저 개발자 도구(F12 → Ctrl+Shift+M)로 한다.

## 5. 내 페이지 만들기

### 경우 1. 이미 있는 빈 페이지 채우기 (대부분 이 경우)
- 내 페이지 폴더는 이미 있다. (예: src/pages/people-org-chart/)
- 지금은 "준비 중" 빈 틀을 쓰고 있다. 이걸 내 화면으로 바꾸는 게 내 일이다.
- 가짜 데이터는 src/data/(내 페이지 이름).ts 새 파일에 만든다.
- 스타일은 내 폴더에 (페이지 이름).css를 만들고, 클래스 이름 앞에 페이지 이름을 붙인다.
  예) org-chart-card, org-chart-title
- 지시: "docs/(내 페이지 문서).md 읽고 계획 먼저 보고해 줘."

### 경우 2. 새 페이지 추가하기 (목록에 없는 페이지)
1. 비슷한 페이지 폴더를 복사하고, 이름 3군데를 새 이름으로 바꾼다
   (폴더·파일 이름, 컴포넌트 이름, 데이터 키)
2. src/routes.tsx에 2줄 추가 (불러오기 1줄 + 주소 1줄) → 사이드바 메뉴는 자동으로 생긴다
3. src/data/에 새 페이지 가짜 데이터 파일 추가
- 지시: "(페이지 이름) 페이지를 새로 추가해 줘. docs/00-팀원-안내.md 5번 경우 2 절차대로 해 줘."

### 경우 3. 기존 페이지 맡기 (로그인·평가 목록·내 평가 결과·대시보드)
- 이 4개는 스타일 이름에 페이지 이름이 안 붙어 있다. (.hero, .donut 등)
- 다른 작업 전에 먼저 이름부터 바꾼다.
- 지시: "(페이지) 폴더의 CSS 클래스 이름 앞에 페이지 이름을 붙여 줘. 화면은 바뀌면 안 돼.
  바꾸기 전후 화면이 같은지 비교해서 보고해 줘."

## 6. Claude Code 지시 예시 (복사해서 쓰기)

### 기본 원칙
- 고치기 전에 항상 "계획 먼저 보고해 줘. 파일은 아직 고치지 마."
- 결과가 오면 localhost에서 직접 확인한 뒤 "커밋해 줘"
- 모르는 단어가 나오면 "쉽게 풀어서 설명해 줘"

### 자주 쓰는 문구
| 언제 | 지시 |

| 계획 받기 | docs/(내 페이지 문서).md 읽고 계획 먼저 보고해 줘. 파일은 아직 고치지 마. |
| 승인 | 계획 승인. 진행하고 pnpm build, pnpm exec tsc --noEmit 결과 보고한 뒤 멈춰 줘. |
| 세이브 | 커밋해 줘. 메시지는 "(페이지): (한 일)". |
| 올리기 | 내 브랜치를 GitHub에 올려 줘(push). |
| 서버 켜기 | pnpm dev로 개발 서버 켜 줘. |
| 되돌리기 | 마지막 커밋 이후 바뀐 걸 보여 줘(git status). 되돌릴지는 내가 정할게. |
| 끊겼을 때 | 아까 작업이 중간에 끊겼어. 마지막 커밋 이후 바뀐 파일 보여 주고 어디까지 했는지 보고해 줘. |

## 7. 막혔을 때

| 증상 | 해결 |
|---|---|
| corepack enable pnpm에서 EPERM 오류 | 관리자 권한 PowerShell에서 다시 실행 (창 위치가 C:\WINDOWS\system32인지 확인) |
| 관리자 PowerShell인데 위치가 C:\Users\... | 관리자 권한이 아님. 닫고 "관리자 권한으로 실행"으로 다시 열기 |
| pnpm -v가 10.x가 아님 | 프로젝트 폴더 안에서 확인했는지 확인. 폴더 안에서는 10.34.3이 나와야 함 |
| git, node, pnpm 명령을 못 찾음 | 설치 후 Claude Code 앱을 껐다 켜기 |
| GitHub 로그인 창이 안 뜨고 실패 ("User cancelled dialog") | 프로젝트 폴더 주소창에 powershell 입력 → git ls-remote origin 실행 → 뜨는 창에서 브라우저로 로그인 |
| localhost:8443이 안 열림 | 개발 서버가 꺼진 것. "pnpm dev 켜 줘" |
